# G10-C语音网关明日实机测试说明

## 一、拿到主机后先做什么

将整个`VoiceGateway-G10C-Test`文件夹复制到G10-C，例如放到`D:\VoiceGateway-G10C-Test`。该测试包包含EXE、运行库和离线模型，不要求G10-C预装Python，也不需要联网。

本说明中的`01`至`04`脚本用于分项测试。完成测试后，日常连续运行应改用`05-web-manager.cmd`；不要让`03-run-live.cmd`和`05-web-manager.cmd`同时占用麦克风。

接好无线话筒接收机到主机粉色3.5mm麦克风输入后，在Windows 10中完成三项设置：

1. “设置→隐私→麦克风”中允许桌面应用访问麦克风。
2. “声音→录制”中确认粉色接口对应的输入设备已启用，并设为默认设备。
3. 暂时关闭该输入端点的“独占模式”和过强的音效增强，输入级别先从50%开始。

## 二、严格按以下顺序测试

### 1. 环境与模型自检

双击`01-doctor.cmd`。模型项目应全部显示“正常”，并能看到至少一个录音输入设备。退出码为0表示通过。

### 2. 3.5mm输入与电平测试

双击`02-probe-mic.cmd`，直接回车使用Windows默认输入，或者输入doctor列出的设备编号。随后用无线话筒连续正常讲话8秒。

结果判断：

- `status=ok`：可以进入语音链路测试。
- `status=no_signal`：没有有效信号，检查粉色接口、接收机输出、Windows输入选择。
- `status=too_quiet`：信号过小，适当提高Windows输入级别或接收机输出。
- `status=clipping/too_loud`：信号过大，降低接收机输出或Windows麦克风增益。
- `dropped_blocks`必须为0。

如果无论如何调节都严重失真，优先判断C782E接收机输出是否为线路电平；此时可能需要无源衰减/隔离线，但仍不代表需要USB声卡。

### 3. 不接现场话筒的离线闭环测试

双击`04-offline-demo.cmd`。它会测试“你好思德→VAD→中英混合ASR”，期望输出包含：

```text
你好思德
请介绍一下这个AI展项有什么功能。
```

退出码为0表示软件、模型和EXE打包均正常。

### 4. 真实话筒测试

双击`03-run-live.cmd`，选择与第2步相同的设备。模型加载完成后按以下方式讲话：

```text
你好思德
（停顿约0.3至0.8秒）
请介绍一下这个AI展项有什么功能
```

再测试至少以下句子：

- 你好思德，请问展厅几点开放？
- 你好思德，What is this AI system used for?
- 你好思德，请介绍一下digital human的主要功能。

每次只唤醒一次、提一个问题，说完停顿约1秒。按`Ctrl+C`停止。

## 三、明日记录哪些结果

每次测试记录：输入设备编号、Windows输入级别、RMS/Peak、是否唤醒、识别文本、语言类型、现场噪声和问题描述。`logs`目录包含北京时间可读日志和完整JSONL事件日志；`results`目录只保存ASR结果及最近一次结果快照，最多保留30天，并受磁盘容量上限约束。

建议最低完成20次正式唤醒、10次相近但不应唤醒的短语、20条中文问题、10条中英混合问题。明日测试的目标是确定接口、电平和主链路可用，不以这几十条样本直接宣称企业级准确率达标。

## 四、当前测试版边界

这是可搬运的现场测试EXE，已经具备离线KWS、VAD、自动中英ASR、有界日志、模型完整性检查、麦克风断连重试、语音子进程监督恢复、唤醒后超时恢复和基础领域纠错。`05-web-manager.cmd`可以在Web管理进程异常退出后进行有退避的恢复，但它尚未注册为Windows Service或开机任务，也不能让断电或关机的电脑自行启动；当前也尚未接入数字人/中控接口。
