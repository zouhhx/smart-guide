# 手机按下麦克风打断目标屏播报

更新：2026-09-10。已在 61 中控和 28（2 号屏）部署并联调。当前支持本地 Qwen3 TTS。手机 APK 本身未在本次修改，按下面协议接入。

**手机端本次只增加一个动作：用户按下说话按钮时，立即调用下面的打断接口。原有“按住说话、松手发送”流程保持不变。话筒端的本地 ASR 与这次手机改动无关。**

## 接口

`POST http://192.168.16.61:3001/api/speech-interrupt`

`Content-Type: application/json`

```json
{
  "target": "2",
  "requestId": "mic-press-9ca7d36b-49eb-4be3-9b47-412933996452"
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| target | 是 | 正整数屏号，数字或字符串均可。例如 `2` / `"2"` 是 2 号屏；不是主机 IP 尾号 28。不接受 all、IP 或空值，不默认选择屏幕。 |
| requestId | 是 | 每次按下产生一个新的 UUID，最长 128 字符。同一次按下的网络重试必须复用该值。不同手机也要使用不同 UUID。 |

现有 `/api/remote-control` 不支持 `stop_speech` 动作；不要往该接口盲发这个 action。旧 `/api/tts-live` 的 `action: "stop"` 固定使用后台选择的数字人目标，也没有完整的旧轮结果拦截，手机请使用新接口。

## 成功响应

HTTP **202 Accepted**，包括无播报时：

```json
{
  "ok": true,
  "status": "DISPATCHED",
  "target": "2",
  "requestId": "mic-press-9ca7d36b-49eb-4be3-9b47-412933996452",
  "cutoffSeq": 5,
  "canceledGenerations": 1,
  "seq": 6,
  "delivered": true,
  "staleResultsBlocked": true,
  "playbackConfirmed": false,
  "queueClearRequested": true,
  "serverTime": 1789023987613,
  "replayed": false
}
```

- `DISPATCHED` / `delivered`：中控已经通过目标屏的 WebSocket 下发优先停止命令。**不是扬声器停止的客户端 ACK**。当前协议没有执行回执，所以 `playbackConfirmed` 始终为 false。
- `staleResultsBlocked`：中控已建立该屏的旧轮结果拦截。打断前已受理的问答即使稍后生成完成，也不会再向该屏下发播放或展示动作。其他屏幕不受影响，下一轮新请求正常工作。
- `cutoffSeq`：被拦截的中控轮次上界，仅用于诊断；手机不要自行生成或比较它。
- `canceledGenerations`：本次实际取消的该屏服务端 TTS 生成/等待请求数。为 0 不代表错误，也不能单凭该字段判断扬声器之前是否正在播放；音频可能已经生成完、尚在客户端播放。
- `queueClearRequested`：停止命令包含清理客户端待播任务的语义。15 版客户端立即取消当前音频，清除排队的语音、问答及讲解任务，不等待慢 PPT 命令完成；PCM 输出缓冲也随取消释放。不会切换首页、隐藏数字人或修改全局静音/音色。
- `replayed`：同一 `target + requestId` 重试返回原结果，不再次停止新一轮音频。幂等记录保留 10 分钟，仅在当前中控进程内有效。手机只做短时间重试，不把旧打断任务持久化到下次启动后补发。

没有播报、没有待播任务时仍返回 202：建立旧轮拦截并发送一次安全的停止命令，页面保持不变。它不是持续静音开关，之后的新问题仍会播报。

## 异常响应

| HTTP | status / error | 语义 |
| --- | --- | --- |
| 400 | TARGET_REQUIRED / REQUEST_ID_REQUIRED | 字段缺失或格式不正确，未打断。 |
| 404 | SCREEN_NOT_FOUND | 屏号未注册，未打断。 |
| 405 | METHOD_NOT_ALLOWED | 仅支持 POST。 |
| 409 | CLIENT_UPGRADE_REQUIRED | 目标屏仍是旧客户端，不能保证绕过忙队列即时打断，未宣称成功。 |
| 409 | TTS_PROVIDER_UNSUPPORTED | 当前切回了旧数字人/讯飞方案。本接口的完整保证针对本地 Qwen3，不冒充支持旧厂商播放队列。 |
| 503 | TARGET_OFFLINE | 中控已拦截该屏旧轮结果并取消本机登记的生成，但停止命令未送达屏幕，`ok:false`、`delivered:false`。不能声称现场音频已停。 |
| 429 / 500 | error | 服务忙或异常，不能当成功处理。 |

目前 2 号屏已升级，注册版本为 `2.0.0+speech-interrupt-v1`；4 号屏（192.168.16.50）仍旧版，会返回 CLIENT_UPGRADE_REQUIRED，需要升级展示客户端后再使用完整即时打断。没有修改 4 号屏。

## 手机接入时序

1. **按下说话按钮**：读取当前目标屏号作为 `target`，生成本次打断的 `requestId`，立即异步 POST `/api/speech-interrupt` 一次。同时照常执行手机原有的按住说话逻辑，不等待打断响应才允许说话。
2. **按住期间**：不循环发送打断请求，不接入或改造 ASR 服务。
3. **松手**：保持现有发送逻辑，仍通过原 `/api/asr-text` 提交新问题；不新增“等待打断成功才能发送”的步骤。一次按住操作的打断与问题应使用同一个目标屏号。
4. 同一次按下不要重复触发接口。若实现短时间网络重试，必须复用同一 `target + requestId`；松手发送新问题后不要再补发旧打断请求。

`/api/asr-text` 的请求格式不变，例如：

```json
{
  "text": "介绍一下你自己",
  "target": "2",
  "source": "asr-apk",
  "requestId": "question-another-new-uuid"
}
```

不要传 `suppressTts:true` 或 `clientMode:"ROBOT"`，它们会抑制展屏播报。空文本、取消录音不提交问题，但按下产生的打断仍然有效。

若打断失败，可以提示目标离线或需要升级，不把失败误当成已打断；不因此改造手机现有的语音识别和松手发送流程。

中控只禁止旧轮结果进入展示/播放链路；旧模型计算可能继续完成并保留后台回答记录。这不代表重新播报。

## 手机端验收

让 2 号屏数字人正在回答，然后按下手机说话按钮：应在按下时停止播报，不等松手。继续说话并松手后，新问题按原流程发送并正常回答。无播报时按下也应能正常使用。另测试快速按下松手，确认旧打断没有延后停掉新回答。

## 已验证

- 本地服务端回归：按屏隔离、旧结果迟到拦截、广播只排除被打断屏、下一轮恢复、并发重试幂等、参数校验、空闲、离线、旧客户端、PCM 断流取消。
- 28 隔离客户端：模拟 PPT 命令忙且队列满，取消语音约 14.4ms，清掉 31 条待播命令，保留翻页命令和当前画面，新一轮仍可入队。该时间是测试中的客户端取消任务耗时，不是手机到扬声器的端到端保证。
- 正式 HTTP→2 号屏：播放中的台湾腔 PCM 被取消；旧 LLM 轮次 5 在打断后约 2 秒返回但未再下发 show_qa；新轮次 7 正常播放完成。打断 HTTP 返回约 10～21ms（有限次局域网测试，不是 SLA）。
- 手机端还需接入按下事件并现场联调；尚未宣称 APK 已改好。本次不涉及话筒端本地 ASR。
